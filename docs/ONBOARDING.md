# V2CC Mac mini 机主接入与交付操作手册

从一台新 Mac mini 到手，到交付给客户使用的完整操作顺序。每一步写明执行账户、命令、
预期结果、异常处理和验证状态。脚本的名称、参数、提示和输出都取自本仓库当前的
脚本，本手册不改变任何脚本行为；脚本细节以 [README.md](../README.md) 和
[docs/test-plan.md](test-plan.md) 为准。

本手册是文档，不是授权。在真实机器上切换系统配置、关闭 FileVault、开启自动登录、
重启和断电测试，每一项都要按现行规则单独获得批准。

## 角色和账户

| 名称 | 含义 |
| --- | --- |
| 机主 | 这台 Mac mini 的所有者，机器放在机主处 |
| 运营方 | V2CC 平台一方，在自己的电脑上生成入口命令，指导和验收 |
| 客户 | 最终通过远程桌面使用 `v2cc` 账户的人 |
| `<机主管理员>` | 机主自己的本机管理员账户。占位符，手册和仓库里不写真实账户名 |
| `v2cc` | 给客户使用的独立管理员账户，部署和自动登录都在这个账户里做 |
| 测试机 A、测试机 B | 两台实测过的 Mac mini。手册里只用这两个代号 |

通用规则：

- 遇到"异常处理"里写的停止条件就停下，保留终端的全部输出，交给运营方，不要手工绕过。
- 脚本都不用 `sudo` 启动。需要管理员授权时脚本会说明原因，再由 macOS 询问当前账户的
  登录密码。
- 不写绝对承诺。本手册只记录观察到的结果。这些设置不保证机器永不重启，也不保证停电后
  一定能远程连接（见 README「7×24 在线设置」）。
- 密码、令牌、入口命令、UU远程 的设备代码、序列号、IP 地址、主机名、真实账户名、
  人名、电话和地址，都不写进本仓库、GitHub 的 issue 或 PR、截图和聊天记录的存档里。

## 已定规则和待定决定

已经决定，本手册照此执行：

- 机主保留自己的本机管理员账户 `<机主管理员>`，密码只有机主知道。
- `v2cc` 是另外单独建的管理员账户。
- `v2cc` 的密码只在现场由人在提示下输入，不写进脚本、仓库和命令历史。
- FileVault 只能由机主本人在知情同意之后关闭，告知内容必须写明物理接触的风险
  （第 10 节）。脚本和运营方都不替机主关闭。
- macOS 更新不自动安装，由人在提前通知的维护时段里手工安装。
- 不做绝对承诺，只写观察到的结果。

尚未决定，下面这些在手册里只作为待定项出现，不是规则：

| 待定项 | 现状 |
| --- | --- |
| 谁负责安装 macOS 更新，什么时候装 | 部署之后机器不再自己安装更新，在定下负责人和时段之前，安全修复会落后 |
| 全新的客户机器能否让客户账户自动登录 | 脚本目前的行为：在空白机上直接用 `v2cc` 部署时，`v2cc` 是唯一受管理的账户，允许为它开启；机主账户是主用户并且本机还管理着其他账户时，机主账户会被拒绝 |

## 5. 用脚本部署开发环境

部署由一条入口命令完成：下载部署包、校验 SHA-256、解压到 `~/v2cc-mac-setup`，然后
运行 `bootstrap.sh`，依次做 7 步。

| 步骤 | 内容 | 已具备时 |
| --- | --- | --- |
| `[1/7]` | 检查机型、系统版本、管理员身份、磁盘空间 | 不满足则停止 |
| `[2/7]` | Xcode Command Line Tools | 跳过 |
| `[3/7]` | Determinate Nix（固定版本，校验 SHA-256） | 跳过 |
| `[4/7]` | Homebrew（固定版本的官方安装脚本，校验 SHA-256） | 跳过 |
| `[5/7]` | 构建系统配置（含 7×24 在线设置）、检查不影响现有账户、切换 | 已是当前系统则跳过 |
| `[6/7]` | Claude Code（官方安装脚本） | 跳过 |
| `[7/7]` | 部署后验证，包括检查没有遗留 GitHub 凭据 | 每次都做 |

**5.1 部署前记录机器现状（只读）**

- 执行账户：`v2cc`
- 命令（都不改动任何东西，取自 test-plan C 节阶段 0）：

  ```sh
  sw_vers
  pmset -g custom
  pmset -g cap
  pmset -g sched
  fdesetup status
  sysadminctl -autologin status
  ls -l /etc/kcpassword
  defaults read /Library/Preferences/com.apple.SoftwareUpdate
  softwareupdate --history
  ```

- 预期结果：得到"改动前"的完整输出，作为人工备份。其中 `fdesetup status` 说明
  FileVault 是开还是关，它决定第 7 到第 9 节怎么做。`/etc/kcpassword` 不存在是
  正常的
- 异常处理：无。输出里可能有主机名等信息，只保存在仓库之外
- 状态：【仅自动化测试或演练验证】这类只读命令在运营方的 Mac 上运行过，脚本对
  其中几项输出的解析也在那里核对过；没有在测试机上运行的记录

**5.2 运营方生成演练入口命令**

- 执行账户：运营方，在自己的电脑上（已用 `gh` 登录 GitHub，并且能读取本仓库）
- 命令：

  ```sh
  tools/make-entry-command.sh --dry-run
  ```

- 预期结果：先显示仓库、版本（提交号）、部署包 SHA-256，以及"这是演练命令：只检查
  并报告，不安装、不改动系统。"，然后输出一整行以 `V2CC_DRY_RUN=1 /bin/bash -c`
  开头的命令。把这一整行原样发给现场操作的人

## 6. 7×24 在线设置（电源和休眠）

这些设置不需要单独的命令：它们是系统配置的一部分，在 5.4 的 `[5/7]` 激活时写入。
它们是 macOS 的整机设置，对本机所有账户生效，包括机主账户。

| 设置 | 值 | 方式 |
| --- | --- | --- |
| 系统空闲时自动睡眠 | 关闭（显示器仍按原设置自动关闭） | `pmset -a sleep 0` |
| 断电后恢复供电时自动开机 | 开启（本机没有这项设置时跳过） | `pmset -a autorestart 1` |
| 唤醒以供网络访问 | 开启（本机没有这项设置时跳过） | `pmset -a womp 1` |
| 闲置后自动退出登录 | 关闭 | `AutoLogOutDelay = 0` |
| 自动安装 macOS 更新 | 关闭 | `AutomaticallyInstallMacOSUpdates = false` |

- 改动之前，激活脚本先把原值记到 `/var/db/v2cc/always-on-before.txt`，只记一次。
  本机支持的电源设置里只要有一项原值读不出来，就在这里停止，一项都不改。
- 设置只在部署激活时写入，不在每次开机时重写。之后有人在系统设置里改了某一项，
  脚本不会改回去，`./verify.sh` 会报告出来。
- 关闭自动安装更新之后，安全修复不会自己装上，必须有人在维护时段里手工安装。谁装、
  什么时候装尚未决定（见待定决定）。脚本能确认的只是这个开关已经关闭；它在
  macOS 27 上能否挡住更新自动安装和重启，尚未在真机验证（test-plan C 节阶段 4 的
  4.2）。检查更新、更新通知、安全数据和后台安全更新的自动安装都没有动。

## 7. 关闭 FileVault：风险告知与确认

FileVault 开启时，机器重启后停在磁盘解锁界面，要有人在机器旁输入密码；在此之前任何
远程软件都连不上，也无法自动登录。要让机器重启后自己回到 `v2cc` 的桌面，必须先关闭
FileVault。它是整块磁盘的一个开关，关闭后本机所有账户（包括机主账户）的磁盘保护都
降低。脚本不会关闭 FileVault，运营方也不替机主关闭。

## 10. FileVault 风险告知与确认（给机主）

下面是 7.2 使用的告知文字草稿，措辞尚待审定。使用时完整给机主看，不要删减。签过的
确认保存在仓库之外。

> **关闭 FileVault 和开启自动登录之前，请确认你清楚这些后果**
>
> 1. FileVault 是 Mac 的磁盘加密开关，一台机器只有一个，对机器上所有账户同时生效，
>    包括你自己的账户。
> 2. FileVault 开启时，机器每次重启都停在磁盘解锁界面，必须有人在机器旁输入密码。
>    在那之前远程桌面软件连不上。关闭它，是为了让机器在重启或断电恢复后能自己回到
>    `v2cc` 账户的桌面。
> 3. 关闭之后，开机时磁盘自动解锁，不再需要任何密码。你自己账户里的文件也不再有
>    这层保护。
> 4. 开启自动登录之后，这台机器每次开机都直接进入 `v2cc` 账户的桌面。任何能接触到
>    这台机器的人（家人、访客、维修人员、窃贼）打开它，就能使用这个账户：里面的
>    文件、钥匙串里保存的密码、已登录的网站、Claude Code 和 Git 的登录信息。
> 5. `v2cc` 的登录密码会以可以还原的形式保存在这台机器的磁盘上。它只是混淆，不是
>    加密，能在这台机器上取得 root 权限的人可以读出它。
> 6. FileVault 只能由你本人在「系统设置 > 隐私与安全性 > FileVault」里关闭。V2CC 的
>    脚本和运营方都不会替你关闭。
> 7. 你可以撤回：先关闭自动登录，再由你本人重新开启 FileVault 并保存新的恢复
>    密钥。重新开启之后，每次重启又需要有人在机器旁输入密码。
> 8. 这些设置不保证机器永不重启，也不保证停电后一定能远程连接。

## 11. 回退

所有回退命令都在 `~/v2cc-mac-setup` 目录下、由当初运行部署的账户（`v2cc`）运行：
上次部署的记录保存在这个账户的 `~/.local/state/v2cc/last-deploy` 里。回退不删除任何
账户主目录里的文件。回退会改动整机的系统配置，和部署一样需要先获得批准。

| 目的 | 命令 | 实际行为 |
| --- | --- | --- |
| 查看系统配置的历史版本 | `./rollback.sh --list` | 只读，列出历史版本的链接和各自指向的系统配置 |
| 回到上次部署之前的系统配置 | `./rollback.sh` | 显示"回退目标"和"该配置管理的账户"，问一次 `[y/N]`，要求管理员授权，重新激活那个配置，显示"已回退到：..." |
| 回到指定的系统配置 | `./rollback.sh --to <系统配置路径>` | 同上，目标取自参数。不能和 `--settings` 一起使用 |
| 只把 7×24 在线设置恢复为启用前的原值 | `./rollback.sh --settings` | 问一次 `[y/N]`，按 `/var/db/v2cc/always-on-before.txt` 逐项恢复并读回检查，原来没有的设置会被删除，然后把记录改名为 `always-on-before.txt.restored` |
| 关闭自动登录 | `./auto-login.sh disable` | 问一次 `[y/N]`，关闭自动登录，删除 `/etc/kcpassword`、登录后立即锁屏的登录项和标记 |
| 只看将要做什么 | 在上面的 `./rollback.sh` 命令前加 `V2CC_DRY_RUN=1`；`./auto-login.sh disable --dry-run` | 只显示"[演练]"行，不改动。`rollback.sh` 不接受 `--dry-run` 参数，只认环境变量 |

要点：

- 7×24 在线设置保存在 macOS 里，不在 Nix 里，重新激活旧的系统配置并不会撤销它们。
  所以只有回退目标不包含这些设置时，`./rollback.sh` 才会接着恢复它们，并显示"该
  配置不包含 7×24 在线设置：电源、自动退出登录和系统更新设置也会恢复为启用前的
  值。"。在两个都包含这些设置的配置之间回退，设置保持开启。
- 这次部署就是本机的首次部署时，`./rollback.sh` 报"上次部署是本机的首次部署，没有
  可回退的系统配置。"，这时用 `./rollback.sh --settings`。当前系统配置仍然包含这些
  设置，所以在重跑 `./bootstrap.sh` 之前 `./verify.sh` 会报告不一致，重跑之后这些
  设置会再次启用。
- 有设置恢复不了时，记录保留在 `/var/db/v2cc/always-on-before.txt`，处理后运行
  `./rollback.sh --settings` 重试。没有这份记录时脚本报"无法恢复"，设置不能自动
  恢复。
- 其他报错："没有找到上次部署的记录"：用 `--list` 查看，再用 `--to` 指定。"系统
  配置不存在或已被清理"：目标已不在本机，交给运营方。"当前系统已经是该配置，无需
  回退。"：不需要处理。
- 自动登录不随系统配置回退，要单独运行 `./auto-login.sh disable`。它结束时提示两件
  要人工完成的事：修改这个账户的登录密码（它曾以可还原的形式保存在磁盘上）；由
  机主重新开启 FileVault 并保存新的恢复密钥。
- 通过远程会话关闭自动登录或恢复电源设置之前要想清楚：之后的下一次重启会停在登录
  窗口，断电后也可能不再自己开机，需要有人到机器旁。
- 部署时激活失败的自动回退由脚本自己完成（见 5.4），不需要人运行这些命令。

状态：【仅自动化测试或演练验证】这一节的全部命令都只在桩测试里验证过，没有真机
演练记录（待确认事实第 13 条；test-plan 的 B6、C 节阶段 1 的 1.9 和阶段 2 的 2.12）。
